### 正常入口与三条调用链

容器中 `npm run build` 生成 build（含 UI dist）。`npm run dev`、`npm run dev:ui` 分别启动后端和 Vite；`npm start` 启动已编译的应用。生产镜像 CMD 先运行监督进程，另含数据库初始化与降权。质量门禁为 `npm run check`，定向入口有 `npm run lint`、`npm run typecheck`、`npm test` 和 `npm run test:browser`。Compose 正式启动命令为 `docker compose up -d`。[根清单](../../package.json#L11) · [Docker CMD](../../deploy/Dockerfile) · [配置](../../compose.yml)

1. **管理员修改全局录制。** 设置操作进入 PUT recording-default → 统一会话和 Origin 校验 → 归档门面 → 元数据 Worker 在写事务内持久化默认值及目标行 → 事务返回实际目标 ID → 通知录制调度器并协调会话。响应与后续异步录制各有独立可观察结果。[HTTP](../../apps/server/src/http/app.ts#L584) · [归档门面](../../apps/server/src/archive/index.ts#L530) · [写事务](../../apps/server/src/archive/metadata-worker.ts#L1288)
2. **旧库截图任务恢复。** 监督进程先迁移旧 SQLite → 重建派生统计 → 截图队列把中断的 running 放回 pending → 带 claim token 认领 → FFmpeg 渲染、校验、发布文件 → 以相同 claim 更新 done 和计数。重启后可从管理员接口读取成品 JPEG。[启动](../../apps/server/src/deploy/start.ts#L65) · [迁移](../../apps/server/src/database/migrate-deployment.ts#L259) · [统计](../../apps/server/src/previews/job-statistics.ts#L17) · [认领](../../apps/server/src/previews/jobs.ts#L906) · [条件完成](../../apps/server/src/previews/jobs.ts#L1000)
3. **浏览截图并收藏。** 浏览器工作台读取主播和可见时间窗 → 截图路由的 Zod schema 校验时间窗、分页和游标 → 归档提供截图单元及收藏状态 → 截图网格按稳定单元 ID 展示。单击定位回放、双击提交收藏；长按或按住拖动构造起止区间，工具栏根据选中项状态提交显式收藏目标；服务器响应和重新读取共同校正状态。[工作台](../../apps/ui/src/App.tsx#L280) · [客户端请求](../../apps/ui/src/features/snapshots/use-snapshot-view.ts#L295) · [服务端校验](../../apps/server/src/http/previews.ts#L77) · [收藏提交](../../apps/ui/src/features/snapshots/SnapshotGrid.tsx#L394) · [区间算法](../../apps/ui/src/features/snapshots/snapshot-selection.ts#L30) · [真实交互验收](../../tests/e2e/snapshot-gestures.mjs#L113)

## 三、架构评估

服务端由部署监督进程拥有 PostgreSQL 和应用子进程。HTTP 通过端口进入归档、录制、预览、网络和直播。元数据 Worker 的事务与可移植日志共同提供恢复；截图与录像文件还需要文件级提交与恢复。浏览器依赖共享 schema，指针预览、持久收藏状态和播放器位置分别有明确的归属。243 个生产模块的运行时导入图没有环。补充审查发现的两组纯类型环已消除，最终连同类型边一起检查仍为零，原导出路径维持兼容。在读入的 112 个非测试、非基准服务端 TypeScript 模块中（结构表另计 1 个 .mjs 启动桥），ports 收到 35 个直接入边（2 个值引用），provider/http 为 23，database/sql 为 18，sync-clock 为 16。拆分主要权衡是事务一致性、组装成本和回归面。[依赖和事务](runtime.md) · [跨层及扩展成本](structure-ui.md)

## 九、后续建议

按实际风险排序，优先保全停写备份、维持依赖公告检查和验证恢复，再用代表性硬件数据决定性能改造。跨版本恢复与镜像回滚是两项不同操作。若磁盘文件或历史日志已被旧版本删除且无备份，代码回滚无法恢复它们。更多部署边界见[安全与数据保护](../SECURITY.md)及[升级说明](../CONTRIBUTING.md)。
