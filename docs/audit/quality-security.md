# 构建、质量与安全审查

审查对象为单管理员、单库写入的自托管部署。分别检查了仓库、浏览器交付物、npm 依赖和 Linux 发布镜像。操作系统与自带二进制的公告结果见[依赖审查](dependencies.md)。应用测试在临时 PostgreSQL 和隔离 Chromium 中运行。

后续部署决定已关闭 O02。单管理员从工作台状态面板查看故障原因、后台任务和可用的重试操作。面板对归档异常、磁盘不足、站点不可用和后台重试分别显示状态。对应三个测试文件共 15 项通过。[归档状态](../../apps/ui/src/features/status/ArchiveHealth.test.tsx) · [后台任务](../../apps/ui/src/features/status/background-status.test.ts) · [系统面板](../../apps/ui/src/features/status/SystemSummary.test.tsx)

**HTTP 日志等级。** 按请求 ID 可以关联开始、完成和中断。客户端提前断开或 Fastify 抛错会发 warn，完成事件包含状态码和耗时。原来所有完成事件都是 info；健康检查捕获底层故障后直接回 503，按错误级别收集时会漏掉这条故障。D9-06 按最终响应将全部 5xx 完成事件记为 error。恢复到 200 后回到 info。未捕获进程异常另写 fatal，由监督进程负责退出。慢工作台请求在 500 ms 门槛按 10 秒采样一次；这与按状态码设置日志等级分别处理。[请求钩子](../../apps/server/src/http/app.ts#L132) · [真实故障与恢复](../../apps/server/src/http/app.test.ts#L890) · [进程异常](../../apps/server/src/runtime/runtime-logs.ts#L335) · [现有诊断工具](../CONTRIBUTING.md#L99)
