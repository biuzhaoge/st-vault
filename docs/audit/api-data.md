### 表中专属容量

- **登录与初始化。** `/api/login` 与 `/api/setup/session` 的 IP 记录固定窗口为 60 秒，每 IP 最多 10 次，成功后清除本 IP 记录；全局最多记录 1000 个 IP。已配置凭据另有持久的实例级失败计数，每 5 次进入 1、5、15 分钟递增冷却。完成初始化一次最多进行一项。[IP 额度](../../apps/server/src/http/app.ts#L397) · [账户锁定](../../apps/server/src/http/auth.ts#L151)
- **工作台与直播。** 工作台一次最多 24 个主播、720 桶、8 天，每请求 3 个行工作者；正式装配总请求 4–16，总行槽 3–8，满时 429。正式直播总会话按 CPU 限 16–128，每所有者 4–32，在途请求为网络并发预算的 4 倍；回放在接纳时检查最多 50 个会话，成功读取清单会刷新 30 分钟期限。SSE 整体 32 路、每所有者 4 路。[工作台参数](../../apps/server/src/http/app.ts#L494) · [工作台输入](../../apps/server/src/http/workbench.ts#L35) · [直播参数](../../apps/server/src/runtime/execution-policy.ts#L96) · [回放接纳](../../apps/server/src/http/playback.ts#L120) · [SSE](../../apps/server/src/http/sync.ts#L127)
- **媒体、账户与后台。** 预览按通道容量拒绝超额请求，返回 429；媒体选区最多 64 个未退休项，先退休未被引用的旧项，全被固定则忙。删除最多 64 个在途，超出的已确认任务持久排队并自动补位。账户同步和头像分别有业务并发门槛。密钥验证更新时撤销上一次验证。系统重试为同一目标合并运行中的任务和 5 秒内的重复请求。[预览接纳](../../apps/server/src/previews/index.ts#L203) · [选区接纳](../../apps/server/src/archive/media-selection-store.ts#L74) · [删除接纳](../../apps/server/src/archive/deletion-store.ts#L69) · [账户接纳](../../apps/server/src/account/account-sync.ts#L408) · [头像](../../apps/server/src/account/account-sync.ts#L567) · [密钥验证](../../apps/server/src/http/key-validation.ts#L22) · [系统重试](../../apps/server/src/http/system.ts#L226)

本轮保留现有读取路径。合成非空 24 行的十次请求均在 100 毫秒内，48 次 RPC 体现扩展成本，还不足以定位生产慢查询。建议以既有 500 毫秒慢请求诊断为调查入口，先区分队列等待、归档读取和断开后的排空。如果代表性并发场景重复超过此值，可先试“同一行内合并两个读取”，保持当前行预算、取消和语义；这需要扩充归档端口、worker 方法与事务边界。建议验收时在相同数据、硬件与负载下重复三轮，24 行工作台 p95 至少改善 20%，检查录像提交、回放和其他交互读取的 p95 增幅均不超过 10%，继续通过顺序、行槽、拒绝及取消测试。这些比例是后续设计的比较标准，项目当前没有相应的生产 SLO。[慢请求指标](../../apps/server/src/http/workbench.ts#L227) · [同一行的并行读取](../../apps/server/src/http/workbench.ts#L171) · [只读事务与调度](../../apps/server/src/archive/metadata-worker.ts#L1653) · [已有三主体混合负载基准](../../scripts/benchmarks/recording-workbench.mjs#L382)
