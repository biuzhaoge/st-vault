# 主播列表规则

一位主播一条记录，以原站主播 ID 为主键。初次绑定和定期同步均先取得登录账户的完整关注 ID，再按 ID 分批更新资料、关注证据和直播状态。

| 字段                         | 固定来源                                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 绑定账户 ID                  | `/api/front/v3/config/initial-dynamic` 的 `user.id`。                                                                                                                                            |
| 全量关注 ID                  | `/api/front/users/:accountId/favorites` 的 `modelIds`。                                                                                                                                          |
| 主播现名                     | 批量 `/api/front/v2/users` 的 `username`。本地记录已确认的改名历史。                                                                                                                             |
| 主播头像                     | 批量 `/api/front/v2/users/profiles` 的 `avatarUrl`。                                                                                                                                             |
| 基础封面                     | 批量 `/api/front/models/list` 的 `previewUrlThumbSmall`。                                                                                                                                        |
| 直播快照                     | 同一批卡片的 `snapshotTimestamp`，仅在状态明确为公开直播时更新。缺项或状态不明时沿用已有封面，确认离线或私密后使用基础封面。                                                                     |
| 直播状态                     | 公开批量 `/api/front/models/list` 的 `status` 与 `isLive`。状态组合一致才采信，按既有规则记录最近核验时间和本场上线时间。                                                                        |
| 对既有主播的关注核验         | 登录态批量 `/api/front/models/list` 的 `isInFavorites`。同批必须有来自关注索引的已关注对照。                                                                                                     |
| 账号禁用                     | 原站对应直播间页面的同名「账户已被禁用」提示。                                                                                                                                                   |
| 账号删除                     | 单人 `/api/front/v2/users/:id` 的 `isDeleted`。                                                                                                                                                  |
| 地区限制                     | 登录态房间 `/api/front/v2/models/:id/cam` 返回匹配 ID 的 `user.isGeoBanned`。普通 403 时，仅在仍关注且批量状态有效的旧标签上，以同 ID 正规房间页面的 `viewCam.playerIsAvailable=true` 复核解除。 |
| 未获批准                     | 保留最近一次已确认的结果，直到获得能更新该结论的证据。                                                                                                                                           |
| 录制开关、任务状态、最近录像 | 本地策略、录制服务和媒体库。                                                                                                                                                                     |

分批响应需与请求 ID 一致。缺失的资料字段沿用已保存值，首次缺少现名时用 ID 占位。一般直播状态缺项或过期时沿用上次确认的分组。在线公开排在私密之前，各自按本场上线时间倒序。离线与归档按最近可见录像、最近上线排序。自动录制使用当前已确认的公开状态、本地录制开关和可写存储。

取关须同时满足有效索引缺席、带登录对照的同 ID 卡片明确返回未关注、同 ID 账号未删除以及对应直播间可访问。精确账号记录用于校对页面上的当前房间名。证据缺失或请求失败时保留既有成员关系和已确认原因。无已确认限制的归档可在卡片确认关注且账号、页面均已核实时恢复。

核验心跳每次取得新的取关或封禁证据后才允许清理。有录像的条目进入归档，保留录像和取关或封禁标签。已确认无录像的条目从归档列表隐藏，在回收任务完成后清理记录。明确封禁且无录像的条目须先收到原站取关成功响应。单次请求只有一个目标，且有效索引确认该目标缺席时，原站明确返回「没有可删除的收藏」也可作为取关已完成的证据。清理时再次确认绑定代次和媒体状态。

确认地区受限且批量接口提供同 ID 有效状态时，按公开、私密、离线分组。确认地区受限且缺少有效状态时，进入归档并显示地区限制，保留关注与本地数据。2026 年 11 月 27 日本机换线后测得 18 个地区受限样本，匿名和登录态批量卡片均未返回这些条目，房间接口返回 `isGeoBanned=true`、空 `status` 和 `isLive=false`。空 `status` 无法用于确认离线。 [关注索引与资料](../../apps/server/src/provider/account-directory.ts) · [直播状态](../../apps/server/src/provider/live-status.ts) · [归档清理](../../apps/server/src/archive/unfollowed-subjects.ts)
