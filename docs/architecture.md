# 架构与存储

**简体中文** · [English](architecture.en.md)

ST-Vault 面向单管理员、多客户端。React/Vite 工作台通过 REST 与 SSE 连接 Fastify；单容器内运行 Node、PostgreSQL 18 和截图用的 FFmpeg。生产镜像没有浏览器、GPU 解码组件或自动密钥提取器。版本和依赖以 [package-lock.json](../package-lock.json) 与 [Dockerfile](../deploy/Dockerfile) 为准。

## 数据流与模块边界

存储、HLS 对齐和媒体目录日期始终使用 UTC。部署 `TZ` 经服务端校验后由会话接口传给工作台，统一所有客户端的显示时区，与界面语言无关。日历导航使用当地午夜/中午的离散槽位（`@date-fns/tz` 处理夏令时），媒体时长仍取真实 UTC 差值；不能用固定 24 小时替代自然日。

```text
原站 Cookies → 账户资料 / 完整关注清单
匿名状态和 HLS → 每主播共享流入口 → 浏览器直播
                               → 原流落盘 → 录像单元 → 后台截图
浏览器操作 → HTTP → 归档 worker → 媒体库日志 + PostgreSQL 热索引
```

## 状态、录制与网络

“全部主播录制”是持久化的录制默认策略，不是当前列表开关的汇总。设置时在同一归档事务中更新默认值和全部未归档主播；后续新加入或重新关注者继承该值，普通清单刷新及上下线不覆盖单个主播的手动选择。归档仍强制停止录制。策略随媒体库日志恢复，前端通过统一同步通知读取；无既存策略时默认关闭，不推断用户曾经的批量操作意图。

状态是带观测时间与有限租期的证据，不是永远有效的布尔值。失败和 UNKNOWN 不立即改写已知状态，也不续租。不同的已知状态通过追加匿名观测确认，确认后将转换边界回溯到首次有效候选观测；隐私撤销不等历史确认。重启与租期到期保留未知空档，不伪造离线或连续在线。具体实现及故障测试位于 [provider](../apps/server/src/provider) 与 [archive](../apps/server/src/archive)。

历史事件按递增 ID 分页；发生时间与发现时间分开，迟到确认不打乱已读游标。打开历史面板定位到最后一条，随新事件和布局变化继续贴底；向上阅读时保留当前位置。运行事件记录正常关闭和重启后发现的异常关闭；最后心跳只能给出故障时间下界，不能推断精确断电时刻。事件、状态与已读位置进入可恢复媒体库；工作台不再绘制橙色停机覆盖块。

每位主播共享一条正常上游生产链，直播消费内存中的媒体，录制独立顺序提交，不等落盘才供直播。录制保存最高可用源画质，不转码。优先使用 HLS PROGRAM-DATE-TIME 定位墙钟；没有可靠时间的片段保持未定位，不用下载时间冒充源时间。

网站域名在账户连接后锁定，清单与匿名资料、状态共用该来源。HLS 默认节点为 `edge-hls.doppiocdn.net`，后续使用持久化的手动选择。更换节点后，每个生产者取消旧路请求并重新解析所选节点，保留已发布缓冲和录制写队列。测速只由用户发起，顺序对各节点读取最多 2 MiB 的实际分片，结果用于展示和排序。

## 录像单元与前端一致性

完整源分片只能归属一个稳定录像单元。约分钟节奏建立单元，不在自然分钟边界切视频；短暂断流不直接拆成新身份。代表截图优先使用单元首个分片中的可解码画面，增长中的单元保持取样锚点与 URL 稳定。截图、喜欢、删除与回放吸附共同使用单元身份。

直播真实时间、播放游标、已提交末端各自独立。点击截图只定位播放，不冻结直播窗口；拖选才固定范围。服务端生成有限空档与压缩后的分页格位，客户端不能用分钟数推算页码。截图未生成和媒体不存在是不同状态。

喜欢先持久接纳并发布逻辑保护，再分批整理；开放单元后续成员继承保护。删除先接纳持久意图、逻辑隐藏，再准备成员和分批回收；确认时封闭开放单元，之后的新录像不混入旧任务。重启继续未完成步骤。全选使用冻结选择令牌和显式例外，不将全库成员下载进浏览器；个人版本和删除世代阻止迟到结果覆盖新操作。

「删除非喜欢」接纳时确定收藏保护；准备期间取消喜欢时，在同一个持久事务为受影响的删除命令记录排除项。该次删除继续处理原目标，重启后规则一致。界面把因旧版本的收藏变动保护而终止的任务作为历史取消记录，并按各事项的实际状态显示告警。

前端按业务 scope 管读取与取消，SSE 提供失效通知，不能将它当完整业务数据。当前时间线每包三行、两包并行；缓存有界，优先可见行。相同主体对象复用；连接线几何局部订阅；动画按实际几何变化触发，并批量测量后写入。精确播放游标不驱动整块覆盖线，存档时间映射使用累计索引二分定位。

原生滚动保留筛选结果的完整高度，只挂载视口附近的主播行。大幅跳转时，虚拟占位先画出封面框和双轨底稿。相邻屏外行只从本地缓存预取封面，图片队列为可见行保留传输槽。跨行滚动期间暂停目录时间线读取并保留已绘制的详细轨道。新进入视口的行即使有缓存，也先显示封面和双轨底稿，停稳 120 毫秒后再绘制缓存和分批补读。小时网格与直播线共用视口高度，刻度几何由视图边界决定，直播时钟只更新直播线位置。播放器的聚焦时间线独立更新，列表位置恢复与连接线仍使用精确偏移。

滚动停稳、调整跨度、前后翻页或切换筛选后，当前视口的双轨内容按行从上到下错峰淡入，包括已缓存的行。翻页时外层沿用时间轴的横向位移，内层轨道在同一过程中淡入。时间线请求继续并行，较早完成的下方行先进入缓存，等上方的行就绪或显示读取失败后再呈现。等待期间，录像轨道显示浅色扫光，并在内容淡入时同步淡出。持续滚动和屏外占位使用静态底稿，后台刷新保留已呈现的轨道。

浏览器封面缓存保存图像字节。每次挂载生成独立的显示地址，离开视口时释放地址，返回仍可使用缓存字节。

覆盖线每行使用一个 SVG、至多 15 条密度路径，保留空档和不足一像素的画面标记。宽视图尽量采用整分钟分桶，由 PostgreSQL 汇总覆盖数据。覆盖完整的自然分钟直接使用分钟起止边界，部分分钟仍读取真实边界；没有录像覆盖的窗口直接返回空已看区间。有待处理删除时采用可见录像的精确读取。绘制聚合保留截图、选区吸附、喜欢和删除所用的原始数据。

列表排序、筛选及增删共用视口级过渡：先确定最终顺序与浏览锚点，再以 Web Animations 平移可见整行。远处目标截到视口边缘，离场 DOM 只保留约一屏、360ms，不额外挂载远处行或加载其图片；空位自然补齐。连续更新从当前动画位置接续，滚动、拖选、调整视图优先中断动画。封面与时间线同行移动，选区和播放器连接线同步跟随；沿用项目动效时长和缓动，不新增动画依赖。

账户独占封面列的表头，头像和用户名上下排列。筛选器与时间导航共用同一行和控件样式。视图滑块在有明确左右边界的底槽中移动，拖动时维持胶囊轮廓。日期居中放在刻度行，发生碰撞时省略附近的小时数字并保留刻度线。封面列宽从共享行高和 16:9 比例推导，刻度仍对齐时间线起点。虚拟滚动、选区和连接线共用同一行高。

账户、密钥、CDN、设置、状态和历史面板共用弹窗表头、内边距、表单和状态样式。各面板按内容选用宽度档位，同一面板的宽度在中英文间一致。高度随内容调整，超出可用高度时由单个区域负责纵向滚动。

## 并行与任务调度

[execution-policy.ts](../apps/server/src/runtime/execution-policy.ts) 根据有效 CPU、内存和容器限制规划网络、解码、文件 IO、发布及数据库容量。录制路数不设固定上限，但所有缓冲和工作队列仍有资源边界。提高并发不保证机械盘吞吐线性增长。

媒体可见性先定位候选分片或录像单元，再按索引核对已接纳的删除任务。单元删除期间，清单从仍可见的录像单元取最近录像时间。直播、录制调度和图片任务读取主播身份与状态时省去录像排序统计。重叠的清单读取共享一次查询，后台任务状态在后台读取池汇总。已回滚的存储忙请求可以重试，发布结果不确定时继续走归档恢复。状态面板按录制、数据同步、媒体处理、归档与存储四组展示，组内任务逐行显示进度、时间和诊断。归档服务、盘空间、保留期清理和完整性巡检归入同一组，分别报告自身状态。每条重试只执行该事项可独立触发的恢复动作。绑定站点复查验证实际配置响应，归档检查读取媒体、事件和个人标记的索引版本。图片地址版本不变时继续用缓存。静态图片传输出错时核实镜像域名的图片响应，成功后以原内容版本保存并复用可用的线路。例行心跳和手动测速留在各自的诊断或操作入口。

同步心跳仅读取主播状态和媒体、事件、个人标记的版本。完整清单和历史未读统计由相应页面按变化读取。用于读取的 POST 不发刷新通知，新增的已看证据单独通知时间线。时间线聚合在同一查询内取整分钟摘要和边界明细。定位和覆盖重建按实际重叠范围取分片，跨分钟长分片由独立的部分索引覆盖。清理任务按批写入完成标记，并通知实际受影响的录像单元范围。

工作台初读等待 SSE 的 `ready`，最多等待 250 ms。较晚建连和重连按当前视图补读。目录时间线由批读取器负责首读，SSE 订阅负责后续失效。配置的心跳间隔更新时，现有连接继续接收服务端时钟。

[同步状态读取](../apps/server/src/http/sync-state.ts) 依据媒体版本和主播观测生成失效范围。[SSE 传输](../apps/server/src/http/sync.ts) 负责连接、顺序发布和背压。截图、聚焦时间线订阅当前主播，目录批读取器保留现有画面并只重读受影响的行。离开视口的已缓存行返回后再读取。全局失效覆盖同一批次内的定向失效。

[时间线数据订阅](../apps/ui/src/features/timeline/use-track-data.ts) 管理目录和聚焦视图的读取范围、失效和生命周期。[工作台读取](../apps/ui/src/features/timeline/workbench-read.ts) 管理请求参数及删除保护需求。[状态历史读取器](../apps/server/src/archive/status-history.ts) 通过结束时间索引找到跨入窗口的区间，首批同时取回区间数据，后续按起点每批最多读取 128 条。同一次状态历史查询的所有分页共用一个只读快照。

覆盖读取在同一次 SQL 往返中检查该主播的活跃删除任务和仍含未清理片段的已删除录像单元。有活跃任务时直接选择可见片段读取，否则继续检查残留片段。

已看投影从窗口内的可见录像单元出发，逐个按单元主键查已看进度，避免反复扫描其他主播或窗口外的证据。同一次有界查询同时给出已看前缀和实际未看后缀。前端分别将两种颜色绘制在匹配的覆盖上，亚像素空档保持空白，同桶的新分片也保留原有的白色前缀。颜色更新时按原时间坐标重绘，避免旧色块平移或缩放到其它时刻。

[系统状态路由](../apps/server/src/http/system.ts) 通过只读能力汇总状态，与 HTTP 装配分开。系统概况和截图区共用同一份删除任务列表。[删除任务观察](../apps/ui/src/features/snapshots/use-deletion-jobs.ts) 合并状态快照与命令确认，并按任务版本和终态处理迟到响应。列表不可用时可独立补读。

数据库使用普通读取、播放、后台、快照和写入专用池。前台批次与后台有界步骤公平交替，补建录像单元索引属于后台。唯一 journal writer 保证日志顺序与 fsync 一致性。交互和播放只读事务的单条 SQL 上限为 15 秒，连接池等待独立计时。回滚失败的连接直接丢弃。

工作台断开时停止派发新行，覆盖读取退出对共享录像索引的等待。工作台的只读覆盖与状态历史经 RPC 向下传递取消。正在排队借用的连接获准后会归还，已执行的 SQL 结算后回滚对应事务并释放配额。在途 SQL、连接池等待和回滚都会计入请求排空时间。

状态面板聚合同步、封面、录制、截图、删除、喜欢整理、保留清理、完整性与检查点等任务。业务时钟统一调度，慢任务不重叠；解码、重连和超时属于各自操作生命周期，不把每个计时器都变成面板任务。正常退出先停止生产，再排空已接纳工作，最后关闭归档与 PostgreSQL。

排查调度延迟时，先按触发条件定位执行者，再比较时钟的开始和完成时间、任务自身的状态以及资源池等待。

| 执行者                                                                                                                        | 触发和恢复                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |

[录制轮转](../apps/server/src/capture/rotation.ts) 只计算下一个候选与游标，接受紧急集合和在途查询作为输入。普通轮询从游标顺序取候选，有手动请求时再查找优先项。监督器负责时间预算、策略复核、租约和录制世代。

`capture_polling` 在首轮结算和之后至少间隔 60 秒输出时延分布和计数。可分别查看容量等待、上游观察、持久写入确认、扫尾和轮转。任务状态补充观察尚未结算的轮次。截图历史扫描在完整空轮转后按冷却到期或 5 秒复查目录。媒体提交和删除会唤醒相关工作，任务领取仍使用 250 ms 节奏。任务统计随已提交变更和审计刷新。

## 存储与恢复

`data` 保存部署私有配置和 PostgreSQL 热索引；`media` 保存可迁移媒体库。两者可分别挂载 SSD 与机械盘，数据库要求本地文件系统；同一库只允许一个实例写入。

```text
data/
  postgres/18/                    PostgreSQL 集群
  private/                        配置加密主密钥与数据库凭据
  logs/                           轮转日志
  backups/                        存在旧库升级时的冻结副本
media/
  library.json                    库身份与检查点引用
  catalog/                        当前及上一份 NDJSON 检查点
  postgres-journal/               顺序提交日志
  subjects/stripchat-<ID>/
    images/                       封面、头像
    recordings/YYYY-MM-DD/HH/     UTC 日/小时分桶的原始分片
    recordings/unlocated/         未可靠定位的媒体
    recordings/.staging/          尚未发布的写入
    thumbnails/YYYY-MM-DD/HH/     JPEG 与来源校验信息
```

主播键为 `stripchat:<ID>`，名称与自动曾用名只是资料。库内使用相对路径；日/小时分目录控制单目录规模，检索通过数据库索引完成，不在每次请求中扫描录像文件。PIN、Cookies、解密密钥及私有网络配置不进入媒体库检查点。

媒体先临时写入、fsync、原子发布。数据库实际行变更先写媒体库日志并 fsync，再提交热索引并应答。检查点固定一致快照后流式导出，不把全库载入内存；保留当前、上一检查点及恢复所需日志。热索引缺失从检查点和日志恢复，完整记录校验错误或序号缺口明确拒绝，不能吞掉损坏。

截图任务是可恢复的后台工作，已有有效 JPEG 经图片和来源校验后复用。删除物理回收不长期占用录制写锁；同主播有序、不同主播有界并行。已提交墓碑后的文件删除失败进入重试，不将整个媒体库判为损坏。

当前媒体库清单格式为 2，PostgreSQL catalog schema 为 1。保留的旧双目录 SQLite 格式 5 导入是一次性升级通路，不是日常存储。备份、移动及旧版本回退限制见[使用手册](../README.md#备份恢复与更新)与[维护说明](CONTRIBUTING.md#旧部署升级)。
