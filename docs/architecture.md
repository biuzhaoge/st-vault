# 架构与存储

**简体中文** · [English](architecture.en.md)

ST-Vault 面向单管理员、多客户端。React/Vite 工作台通过 REST 与 SSE 连接 Fastify；单容器内运行 Node、PostgreSQL 18 和截图用的 FFmpeg。生产镜像没有浏览器、GPU 解码组件或自动密钥提取器。版本和依赖以 [package-lock.json](../package-lock.json) 与 [Dockerfile](../deploy/Dockerfile) 为准。

## 数据流与模块边界

存储、HLS 对齐和媒体目录日期始终使用 UTC。部署 `TZ` 经服务端校验后由会话接口传给工作台，统一所有客户端的显示时区，与界面语言无关。时间线上限始终是当天结束。导航仍按当地午夜和中午的离散槽位移动，`@date-fns/tz` 处理夏令时。媒体时长使用实际 UTC 差值。

归档按部署时区计算每个日期的第一个实际时刻，并用全库可回放分片的实际重叠判断时间线保留哪些日期。跨午夜的分片保住两侧日期。时间轴仅压缩已结束且全库无录像的整日，最多显示七个可见日。日期刻度、状态、覆盖、拖选与播放定位共用双向映射。跨越长空档时，工作台在同一读取快照中按可见区间取样，媒体路径和时间戳继续使用 UTC。

```text
原站 Cookies → 账户资料 / 完整关注清单
匿名状态和 HLS → 每主播共享流入口 → 浏览器直播
                               → 原流落盘 → 录像单元 → 后台截图
浏览器操作 → HTTP → 归档 worker → 媒体库日志 + PostgreSQL 热索引
```

## 状态、录制与网络

“全部主播录制”是持久化的录制默认策略，不是当前列表开关的汇总。设置时在同一归档事务中更新默认值和全部未归档主播；后续新加入或重新关注者继承该值，普通清单刷新及上下线不覆盖单个主播的手动选择。归档仍强制停止录制。策略随媒体库日志恢复，前端通过统一同步通知读取；无既存策略时默认关闭，不推断用户曾经的批量操作意图。

状态是带观测时间与有限租期的证据，不是永远有效的布尔值。失败和 UNKNOWN 不立即改写已知状态，也不续租。不同的已知状态通过追加匿名观测确认，确认后将转换边界回溯到首次有效候选观测；隐私撤销不等历史确认。重启与租期到期保留未知空档，不伪造离线或连续在线。具体实现及故障测试位于 [provider](../apps/server/src/provider) 与 [archive](../apps/server/src/archive)。

直播状态统一读取绑定站点的 `/api/front/models/list`，按请求 ID 和明确的 `status`、`isLive` 确认状态。每批最多 50 个 ID，只合并进行中的请求。缺项、字段矛盾和请求失败按待确认处理，状态有效期沿用原有观测规则。

历史事件按递增 ID 分页；发生时间与发现时间分开，迟到确认不打乱已读游标。打开历史面板定位到最后一条，随新事件和布局变化继续贴底；向上阅读时保留当前位置。运行事件记录正常关闭和重启后发现的异常关闭；最后心跳只能给出故障时间下界，不能推断精确断电时刻。事件、状态与已读位置进入可恢复媒体库；工作台不再绘制橙色停机覆盖块。

每位主播共享一条正常上游生产链，直播消费内存中的媒体，录制独立顺序提交，不等落盘才供直播。录制保存最高可用源画质，不转码。优先使用 HLS PROGRAM-DATE-TIME 定位墙钟；没有可靠时间的片段保持未定位，不用下载时间冒充源时间。

网站域名在账户连接后锁定，清单与匿名资料、状态共用该来源。HLS 默认节点为 `edge-hls.doppiocdn.net`，后续使用持久化的手动选择。更换节点后，每个生产者取消旧路请求并重新解析所选节点，保留已发布缓冲和录制写队列。测速只由用户发起，顺序对各节点读取最多 2 MiB 的实际分片，结果用于展示和排序。

首次同步和后续同步都从登录态 `/api/front/users/:id/favorites` 读取关注 ID 索引。现名取批量 `/api/front/v2/users` 的 `username`，头像取批量 `/api/front/v2/users/profiles` 的 `avatarUrl`，基础封面取 `/api/front/models/list` 的 `previewUrlThumbSmall`。状态心跳从同一接口读取公开直播的 `snapshotTimestamp` 作为快照版本。快照缺项或状态未确认时保留现有封面，确认离线或私密后恢复基础封面。资料缺项时沿用已有字段，首次缺姓名使用 ID 标签。

对已连接账户，验证身份和关注索引后先把全新 ID 加入目录并通知工作台，慢请求返回后补全资料。常规心跳只批量补查新增或未确认姓名的条目，已有姓名和头像每五分钟核对一次。批量卡片继续提供封面、状态和有歧义的关注证据。首次绑定和换绑由现有的账户与清单原子激活流程处理。

账号禁用以原站直播间页面的同名「账户已被禁用」提示为唯一证据。程序用单人 `/api/front/v2/users/:id` 核对主播 ID 和现名，并从该记录读取 `isDeleted` 判定账号删除。直播间页面用匿名请求读取。无已确认限制的归档可在登录态卡片确认关注、精确账号存在且直播间页面核验完成时恢复。逐人核验按批次轮转。

取关核验使用登录态卡片的明确 `isInFavorites=false`，同时要求同批已关注对照、目标缺席有效索引、精确账号未删除且返回的是同名可访问直播间。缺项或请求失败时保留已有归属。已确认取关或封禁且有录像时保留归档原因。无录像的条目进入后台清理流程并从归档列表隐藏。直播间页面新确认禁用后，无录像的条目通过账户写入队列自动取关，获得原站确认后清理本地。单个目标已缺席有效索引，且原站明确返回没有可删除的收藏时，视为同一取关已完成。录制提交与清理按主播串行，写入前重查绑定代次、现存录像和回收任务。绑定账户更换或断开时撤销旧账户的清理资格。

地区限制由登录态房间返回的同 ID `isGeoBanned` 确认。名单和批量状态恢复后，已有地区限制的条目继续复核。房间接口明确返回 `false` 时撤标。普通 403 时，仍在关注索引、登录态卡片确认在关注且有有效直播状态的条目，可以由同名直播间页面对同一 ID 返回的 `viewCam.playerIsAvailable=true` 确认恢复。证据缺失时保留已有原因。已确认地区受限的主播如果缺少有效的批量状态，进入归档并显示地区限制。能读到状态的地区受限主播按公开、私密或离线分组。地区限制归档保留记录与关注关系，自动录制暂停。

其他条目的批量状态缺项或过期时沿用上次确认的分组。首次未知置于离线筛选末尾，离线计数只包含曾确认离线的条目。列表只显示在线、离线、归档三个分组。在线公开先于私密，各自按本场上线时间倒序。离线和归档按最近录像、最近上线排序。新录制须有当前公开状态、录制开关和可写存储。首个分片提交后才显示录制中。已有播放或录制可按有限证据租期恢复，已明确的私密立即撤销授权。

## 录像单元与前端一致性

删除正在播放的片段后，滚动回看继续跟随直播，手动选定的窗口按剩余录像边界收紧。删除回包丢失时，浏览器按命令 ID 查询回执。历史面板累积多页新事件时，沿服务端游标顺序读取后再更新已读位置。

完整源分片只能归属一个稳定录像单元。约分钟节奏建立单元，不在自然分钟边界切视频；短暂断流不直接拆成新身份。代表截图优先使用单元首个分片中的可解码画面，增长中的单元保持取样锚点与 URL 稳定。截图、喜欢、删除与回放吸附共同使用单元身份。

直播真实时间、播放游标、已提交末端各自独立。点击截图只定位播放，不冻结直播窗口；拖选才固定范围。服务端生成有限空档与压缩后的分页格位，客户端不能用分钟数推算页码。截图未生成和媒体不存在是不同状态。

喜欢先持久接纳并发布逻辑保护，再分批整理；开放单元后续成员继承保护。删除先接纳持久意图、逻辑隐藏，再准备成员和分批回收；确认时封闭选中的开放单元并记录录像版本，之后的新录像不混入旧任务。全选使用冻结选择令牌和显式例外，不将全库成员下载进浏览器；个人版本和删除世代阻止迟到结果覆盖新操作。

删除准备和回收共用 64 个在途名额。超出的已确认任务以 `waiting` 状态写入同一份持久日志。有任务结束或启动恢复时，归档事务按入队顺序补位。工作线程仍按主播有序、跨主播有界并行。恢复仍在等待的任务需要使用支持该状态的版本。

目标单元冻结后，按单元的完整时间边界查找分片，清单页、序号和游标在数据库内写入。每页落盘后可立即开始回收，因此大任务在清单生成期间就能释放空间。被选中的分片批量写入删除标记，文件回收限定为本批次对象。回收目录同步后，在同一次持久事务确认对象和推进任务游标。其他归档回收失败时会独立退避重试，即使保留期设为永久。诊断日志分别记录排队、清单步骤、删除标记、文件和目录回收以及进度确认耗时。

「删除非喜欢」接纳时确定收藏保护；等待或准备期间取消喜欢时，在同一个持久事务为受影响的删除命令记录排除项。该次删除继续处理原目标，重启后规则一致。界面把因旧版本的收藏变动保护而终止的任务作为历史取消记录，并按各事项的实际状态显示告警。

前端按业务 scope 管读取与取消，SSE 提供失效通知，不能将它当完整业务数据。当前时间线每包三行、两包并行；缓存有界，优先可见行。相同主体对象复用；连接线几何局部订阅；动画按实际几何变化触发，并批量测量后写入。精确播放游标不驱动整块覆盖线，存档时间映射使用累计索引二分定位。

原生滚动保留筛选结果的完整高度，只挂载视口附近的主播行。大幅跳转时，虚拟占位先画出封面框和双轨底稿。相邻屏外行只从本地缓存预取封面，图片队列为可见行保留传输槽。跨行滚动期间暂停目录时间线读取并保留已绘制的详细轨道。新进入视口的行即使有缓存，也先显示封面和双轨底稿，停稳 120 毫秒后再绘制缓存和分批补读。小时网格与直播线共用视口高度，刻度几何由视图边界决定，直播时钟只更新直播线位置。播放器的聚焦时间线独立更新，列表位置恢复与连接线仍使用精确偏移。

列表滚动时保留持续可见的双轨内容，新进入的行先呈现封面和轨道底稿，停稳后再按从上到下的顺序补齐轨道详情。调节跨度、前后翻页或切换筛选时，整屏轨道按同样的顺序淡入，翻页同时保留横向位移。时间线请求继续并行，较早完成的新行先进入缓存，等上方尚未呈现的行就绪或显示读取失败后再呈现。等待期间，录像轨道显示浅色扫光，并在内容淡入时同步淡出。后台刷新保留已呈现的轨道。

浏览器封面缓存保存图像字节。每次挂载生成独立的显示地址，离开视口时释放地址，返回仍可使用缓存字节。播放器和监控墙的等待背景使用当前主播的同一张封面，随同步心跳刷新，按原比例完整显示并应用 5px 高斯模糊。

主播封面上显示当前名称。曾用名显示在选中主播的播放器顶部标题栏，位于当前名称下方。

账户连接并提交关注清单后，后台立即排队预取所有关注主播的头像和默认封面。后续使用清单的定时刷新检查新增主播和图片地址变化。来源版本未变且本地图片有效时复用已有文件。默认封面与直播预览分别缓存，直播结束时可直接使用本地默认封面。后台封面更新使用关注清单和状态同步提供的地址，缺少地址时等待新元数据。下载失败时保留已有图片，由业务时钟重试。一次手动重试将所有待重试的封面按现有并发限制分批处理。

主播列表和截图区的两条时间线共用固定的中性玻璃底轨，加载和横向切换的动效作用于数据层。状态与录像各按实际时间着色，未录到画面的区间只显示底轨。每种覆盖颜色使用一个 SVG，至多 15 条密度路径，保留空档和不足一像素的画面标记。宽视图尽量采用整分钟分桶，由 PostgreSQL 汇总覆盖数据。覆盖完整的自然分钟直接使用分钟起止边界，部分分钟仍读取真实边界；没有录像覆盖的窗口直接返回空已看区间。有待处理删除时采用可见录像的精确读取。绘制聚合保留截图、选区吸附、喜欢和删除所用的原始数据。

列表排序、筛选及增删共用视口级过渡：先确定最终顺序与浏览锚点，再以 Web Animations 平移可见整行。远处目标截到视口边缘，离场 DOM 只保留约一屏、360ms，不额外挂载远处行或加载其图片；空位自然补齐。连续更新从当前动画位置接续，滚动、拖选、调整视图优先中断动画。封面与时间线同行移动，选区和播放器连接线同步跟随；沿用项目动效时长和缓动，不新增动画依赖。

在线、离线和归档可独立切换。玻璃高亮表示选中，列表按这个顺序显示选中的分组。在线主播优先显示公开，再显示私密。同一状态内按本次上线时间从新到旧排列。离线和归档均先按最近录像时间，再按最近在线记录排序。筛选组合随当前管理员的视图偏好恢复，旧版保存的单项仍可读取。从历史定位主播时会补选对应分组。

监控墙使用同一份实时目录和在线排序，显示全部在线主播。玻璃底板占用全局标题栏下方的区域，网格按可用宽高安排 16:9 画面。用户名常显在左上角，返回按钮悬浮在网格上方。公开画面复用播放器的媒体层和等待提示，私密画面显示封面与状态。每格独立持有静音播放会话，连接故障最多自动重试三次。主播转为私密或离开在线组时释放会话。退出时立即切回工作台，监控会话在后台释放，工作台的直播请求在释放结算后发出。并发上限继续由直播代理统一管理，名额已满时该画面等待可用会话。

账户按钮居中放在序号与封面合用的表头区域，头像和用户名上下排列。筛选器与时间导航共用同一行和控件样式。视图滑块在有明确左右边界的底槽中移动，拖动时维持胶囊轮廓。日期居中放在刻度行，发生碰撞时省略附近的小时数字并保留刻度线。序号从 1 开始为当前筛选和排序后的完整列表编号，点击区域透明，玻璃高光只绘在数字字形内。数字居中位于行左缘与封面之间。虚拟滚动保留实际行位，封面维持完整 16:9 空间，表头、刻度和时间线采用同一列宽。播放器连线以红色环形节点标记当前主播行左边界的中点。滚出视口时，连线在对应的列表边缘用箭头指示方向。

点击列表序号即可切换该主播的自动录制。银色数字表示关闭，浅红表示已开启，鲜红表示正在录制。悬停或键盘聚焦时，数字在原位切换为录制圆环或停止方块，启动或停止处理中在同一个位置显示进度指示。账户已绑定时，可操作行在序号下方显示取关图标。原站确认后，有录像的主播显示为「已取消关注」，无录像的进入清理。地区限制继续受到保护。工作台以标识亮面的红色绘制播放器连线、主要操作和录制标记。连线由实线、淡光晕与流动提示组成，减少动态效果模式保留实线与光晕。在线、播放和成功使用共享的薄荷绿，告警和一般线路质量使用琥珀色，处理中使用中性文字和进度指示。截图收藏使用独立的粉色。

工作台只在满足尺寸要求的横向视口显示。顶部控件共享响应式高度。播放器和截图按各自容器宽高排版，时间尺和每行轨道共享实际可用宽度。触屏下序号栏会加宽，以在栏内为录制开关提供 44 × 44 像素的点击区域。列表的竖向手势由浏览器原生滚动处理，横向拖动可取段。截图快滑与拖选时停留在上下边缘共用分页状态和动效。浮动菜单按浏览器的可视区域定位，以便在软键盘占用空间时继续操作。

全屏播放器的操作标签避免在点按或拖动时生成文字选区。侧栏的展开与折叠按钮用中性的按钮表面提示键盘焦点。

拖选按录像单元 ID 记录经过的截图，并按当前区间端点计算粉红预览。跨页时跳过空档，拖回时缩小区间。工具栏在预览期间显示选中数量。松手后提交确切的单元 ID，服务端按同一版本翻转各自的收藏状态，并在一个事务中接纳两组结果。取消或失去指针捕获会清除预览。

普通模式下，单击的反馈来自画面轻缩和回弹，回弹时长对应双击判定窗口。第二次按下同一张时，画面从当前姿态衔接到收藏的轻晃反馈。手势由固定大小的按钮接收，只有确认单击才跳播。减弱动态效果时，以静态播放标记和爱心显示操作结果。左上角爱心、选区轮廓和居中播放标记可以同时显示，只有当前播放的截图带底部渐变。跟随播放和后台刷新只更新状态。

账户、密钥、CDN、设置、状态和历史面板共用弹窗表头、内边距、表单和状态样式。设置和状态沿用历史的正文与紧凑间距，两者的分组标题复用历史日期的左右分界线。状态标准行高与历史事件行对齐，说明在对应任务行内单行显示，超出的文字可通过说明按钮阅读。各面板按内容选用宽度档位，同一面板的宽度在中英文间一致。高度随内容调整，超出可用高度时由单个区域负责纵向滚动。

## 并行与任务调度

周期同步的前两轮连续失败仅在状态面板对应行显示灰色提示。连续第三轮未完成时，该行和工具栏的状态按钮显示异常，实际同步成功后恢复。图片下载按单张图片计算连续失败。周期同步会自动继续，需要更新账户 Cookies 时单独提示。

首次前台读取发现封面地址后，若图片下载暂时失败，后台保留该地址用于重试。新的账户清单或离线状态可以取代这个地址。重试结果取决于真实的下载与缓存写入。

运行设置仅提交当前用户编辑的字段。自动保留清理在每一批写入删除记录时核对本轮采用的保留天数。保存永久保留或调整天数后，旧策略下尚未提交的删除停止，已经提交的删除可以完成文件回收。手动删除使用用户确认的范围。

无录像日期清理由业务时钟单独调度。服务启动后补扫，在当地午夜过一分钟及每小时检查一次。已确认的录像删除任务完成后，下一次可用的资源心跳也会重扫。午夜后留出的一分钟用于等待分片落盘。当天历史始终保留，每批写入前在归档事务内重新核对有无录像，待删除的分片在完成归档删除前继续保护当天历史。清理分批移除主播状态区间、历史事件、过期覆盖汇总和完全落在空档内的已结束运行记录。跨越空档的状态区间保留两侧，正在运行或跨越保留日期的运行记录继续保留。录像文件、设置、诊断日志和幂等记录由各自的生命周期管理。`STV_CLEAN_EMPTY_DAYS=0` 只关闭历史清理。

若配置卷或数据库卷低于最低剩余空间，录制和自动清理都会暂停。共用磁盘时应先在媒体库之外释放空间，或扩容，再重试磁盘检查。若只有独立媒体卷低于阈值，已配置的自动清理仍可运行。

[execution-policy.ts](../apps/server/src/runtime/execution-policy.ts) 根据有效 CPU、内存和容器限制规划网络、解码、文件 IO、发布及数据库容量。录制路数不设固定上限，但所有缓冲和工作队列仍有资源边界。提高并发不保证机械盘吞吐线性增长。

媒体可见性先定位候选分片或录像单元，再按索引核对已接纳的删除任务。单元删除期间，清单从仍可见的录像单元取最近录像时间。直播、录制调度和图片任务读取主播身份与状态时省去录像排序统计。重叠的清单读取共享一次查询，后台任务状态在后台读取池汇总。已回滚的存储忙请求可以重试，发布结果不确定时继续走归档恢复。状态面板按录制、数据同步、媒体处理、归档与存储四组展示，组内任务逐行显示进度、时间和诊断。归档服务、盘空间、保留期清理和完整性巡检归入同一组，分别报告自身状态。每条重试只执行该事项可独立触发的恢复动作。绑定站点复查验证实际配置响应，归档检查读取媒体、事件和个人标记的索引版本。图片地址版本不变时继续用缓存。静态图片传输出错时核实镜像域名的图片响应，成功后以原内容版本保存并复用可用的线路。例行心跳和手动测速留在各自的诊断或操作入口。

同步心跳仅读取主播状态和媒体、事件、个人标记的版本。完整清单和历史未读统计由相应页面按变化读取。用于读取的 POST 不发刷新通知，新增的已看证据单独通知时间线。时间线聚合在同一查询内取整分钟摘要和边界明细。定位和覆盖重建按实际重叠范围取分片，跨分钟长分片由独立的部分索引覆盖。清理任务按批写入完成标记，并通知实际受影响的录像单元范围。

工作台初读等待 SSE 的 `ready`，最多等待 250 ms。较晚建连和重连按当前视图补读。目录时间线由批读取器负责首读，SSE 订阅负责后续失效。配置的心跳间隔更新时，现有连接继续接收服务端时钟。

[同步状态读取](../apps/server/src/http/sync-state.ts) 依据媒体版本和主播观测生成失效范围。[SSE 传输](../apps/server/src/http/sync.ts) 负责连接、顺序发布和背压。截图、聚焦时间线订阅当前主播，目录批读取器保留现有画面并只重读受影响的行。离开视口的已缓存行返回后再读取。全局失效覆盖同一批次内的定向失效。

[时间线数据订阅](../apps/ui/src/features/timeline/use-track-data.ts) 管理目录和聚焦视图的读取范围、失效和生命周期。[工作台读取](../apps/ui/src/features/timeline/workbench-read.ts) 管理请求参数及删除保护需求。[状态历史读取器](../apps/server/src/archive/status-history.ts) 通过结束时间索引找到跨入窗口的区间，首批同时取回区间数据，后续按起点每批最多读取 128 条。同一次状态历史查询的所有分页共用一个只读快照。

覆盖读取在同一次 SQL 往返中检查该主播已确认且尚未完成的删除任务和仍含未清理片段的已删除录像单元。有未完成任务时直接选择可见片段读取，否则继续检查残留片段。

已看投影从窗口内的可见录像单元出发，逐个按单元主键查已看进度，避免反复扫描其他主播或窗口外的证据。同一次有界查询同时给出已看前缀和实际未看后缀。前端分别将两种颜色绘制在匹配的覆盖上，亚像素空档保持空白，同桶的新分片也保留原有的白色前缀。颜色更新时按原时间坐标重绘，避免旧色块平移或缩放到其它时刻。

[系统状态路由](../apps/server/src/http/system.ts) 通过只读能力汇总状态，与 HTTP 装配分开。系统概况和截图区共用同一份删除任务列表。[删除任务观察](../apps/ui/src/features/snapshots/use-deletion-jobs.ts) 合并状态快照与命令确认，并按任务版本和终态处理迟到响应。列表不可用时可独立补读。

数据库使用普通读取、播放、后台、快照和写入专用池。前台批次与后台有界步骤公平交替，补建录像单元索引属于后台。唯一 journal writer 保证日志顺序与 fsync 一致性。交互和播放只读事务的单条 SQL 上限为 15 秒，连接池等待独立计时。回滚失败的连接直接丢弃。

工作台断开时停止派发新行，覆盖读取退出对共享录像索引的等待。工作台的只读覆盖与状态历史经 RPC 向下传递取消。正在排队借用的连接获准后会归还，已执行的 SQL 结算后回滚对应事务并释放配额。在途 SQL、连接池等待和回滚都会计入请求排空时间。

状态面板聚合同步、封面、录制、截图、删除、喜欢整理、保留清理、完整性与检查点等任务。业务时钟统一调度，慢任务不重叠；解码、重连和超时属于各自操作生命周期，不把每个计时器都变成面板任务。正常退出先停止生产，再排空已接纳工作，最后关闭归档与 PostgreSQL。

排查调度延迟时，先按触发条件定位执行者，再比较时钟的开始和完成时间、任务自身的状态以及资源池等待。

| 执行者                                                                                                                        | 触发和恢复                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| [业务时钟](../apps/server/src/runtime/sync-clock.ts)                                                                          | 每 250 ms 检查，默认每 5 秒到期。运行中的同一订阅跳过重叠轮次，异常记录后在后续轮次重新检查。                                                  |
| [录制监督](../apps/server/src/capture/supervisor.ts) / [状态证据](../apps/server/src/provider/status-evidence.ts)             | 心跳轮转监控，策略和容量变化也可触发协调。到期停止派发新观测，已派发请求和持久化步骤须结算。独立检查录制租约，并在隐私撤销时停止对应录制世代。 |

`capture_polling` 在首轮结算和之后至少间隔 60 秒输出时延分布和计数。可分别查看容量等待、上游观察、持久写入确认、扫尾和轮转。任务状态补充观察尚未结算的轮次。截图历史扫描在完整空轮转后按冷却到期或 5 秒复查目录。媒体提交和删除会唤醒相关工作，任务领取仍使用 250 ms 节奏。任务统计随已提交变更和审计刷新。

## 存储与恢复

热索引单独记录初始检查点是否已经成功恢复。即使检查点序号为 0，恢复途中失败后也可以在原索引上重试。已确认的终态删除命令保留精简回执，因此即使近期任务列表已经裁剪，同一命令重试仍返回原结果。升级前已经丢失且没有可重放日志的收据无法追溯补建。

`data` 保存部署凭据、日志和 PostgreSQL 集群。PostgreSQL 保存热索引和私有配置，`media` 保存可迁移媒体库。数据库目录使用本机文件系统。同一媒体库只允许一个实例写入。

```text
data/
  private/                        配置加密主密钥与数据库凭据
  logs/                           轮转日志
  backups/                        存在旧库升级时的冻结副本
  postgres/18/                    PostgreSQL 集群
media/
  library.json                    库身份与检查点引用
  catalog/                        当前及上一份 NDJSON 检查点
  postgres-journal/               顺序提交日志
  subjects/stripchat-<ID>/
    images/                       默认封面、当前封面和头像
    recordings/YYYY-MM-DD/HH/     UTC 日/小时分桶的原始分片
    recordings/unlocated/         未可靠定位的媒体
    recordings/.staging/          尚未发布的写入
    thumbnails/YYYY-MM-DD/HH/     JPEG 与来源校验信息
```

主播键为 `stripchat:<ID>`，名称与自动曾用名只是资料。库内使用相对路径；日/小时分目录控制单目录规模，检索通过数据库索引完成，不在每次请求中扫描录像文件。PIN、Cookies、解密密钥及私有网络配置不进入媒体库检查点。

媒体先临时写入、fsync、原子发布。数据库实际行变更先写媒体库日志并 fsync，再提交热索引并应答。检查点固定一致快照后流式导出，不把全库载入内存；保留当前、上一检查点及恢复所需日志。热索引缺失从检查点和日志恢复，完整记录校验错误或序号缺口明确拒绝，不能吞掉损坏。

截图任务是可恢复的后台工作，已有有效 JPEG 经图片和来源校验后复用。遇到无法解析的 MP4 分片时，先单独验证目标分片，再从同一录像单元余下的可用分片取图，沿用原有截图锚点和边界。解码器不可用、读取失败或整个范围没有可用画面时，保留对应的失败状态。文件回收按主播有序执行，不同主播有界并行。删除批次读取日志版本遇到繁忙时，原任务进入退避重试，归档保持可用。日志写入结果不确定时进入归档恢复。已提交墓碑后的文件回收失败可独立重试。

当前媒体库清单格式为 2，PostgreSQL catalog schema 为 1。保留的旧双目录 SQLite 格式 5 导入是一次性升级通路，不是日常存储。备份、移动及旧版本回退限制见[使用手册](../README.md#备份恢复与更新)与[维护说明](CONTRIBUTING.md#旧部署升级)。
